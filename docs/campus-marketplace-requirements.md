# 校园二手与代拿微信小程序需求

版本 v0.2 · 需求初稿 · 2026-11-17

## 1. 产品目标与首发范围

我希望同校学生能在一个微信小程序里找到附近的二手物品，也能发布快递代拿、外卖代拿和校外代购需求，由其他学生抢单并完成交付。首版暂按单校区试点，二手物品当面交接，三类任务均在校区约定范围内交付。

| 优先级 | 功能 |
| --- | --- |
| P0 · 首发 | 微信登录、试点成员校验、二手发布与预约、代拿发布与抢单、订单进度、站内通知、举报与运营后台 |
| P1 · 试点后评估 | 多校区、微信订阅消息、收藏、信用评价 |
| P2 · 待单独评估 | 微信支付、平台担保或抽佣、即时聊天、实时定位、跨校配送 |

首版由双方当面自行结算。二手页面显示卖家标价，代拿页面显示发布者填写的酬金。小程序记录预约与履约状态，页面上用“确认交接”和“确认送达”表示实物交付。支付、退款和资金结算流程留待后续评估。

## 2. 用户角色与准入

| 角色 | 权限 |
| --- | --- |
| 微信访客 | 查看产品介绍、试点说明和隐私规则 |
| 试点成员 | 浏览本校区帖子、发布和预约二手物品、发布三类代拿任务、抢单、查看自己的记录、举报和申诉 |
| 运营人员 | 管理试点资格，审核内容，处理举报和争议，限制违规账号 |

- 每位试点成员使用同一账号即可发布任务，也可抢同校区其他成员发布的任务。已有发单记录或正在等待他人接单时，仍可抢其他人的单。二手买卖也使用同一账号。本人发布的帖子无法自行预约或抢单。
- 试点暂用限次、带有效期的校区邀请码。邀请码仅表示试点准入。后续如需校方身份认证，再确认可用渠道和采集范围。
- 列表和分享链接均按校区校验浏览权限。预约、抢单、取消、确认和后台操作由服务端按身份与记录归属逐次校验。

## 3. 二手物品

**发布字段**包括标题、分类、成色、价格、描述、至少一张图片和可交接区域。首发分类包括书籍、数码、生活用品、运动用品及其他。价格可填 0 元，页面显示“免费送”。

**浏览与预约**支持按标题关键字、分类和价格范围筛选。买家发起预约后进入待卖家处理，卖家可以接受或拒绝。每件物品同一时间保留一个有效预约，卖家接受后锁定商品。双方在订单页确认交接时间与地点。

| 状态 | 进入条件与后续操作 |
| --- | --- |
| 在售 | 审核通过后展示。卖家可编辑或下架，买家可发起预约。 |
| 待卖家处理 | 买家已发起预约。卖家拒绝、买家撤回或预约超时后恢复在售。 |
| 已预留 | 卖家接受预约。交接前任一方可取消并填写原因，商品恢复在售。 |
| 待买家确认 | 卖家提交交接确认。买家可确认收货或提交争议。 |
| 已成交 | 买家确认交接。双方可查看历史记录。 |
| 已下架 | 卖家主动下架无有效预约的物品，或运营处置后停止公开展示。已有预约记录对当事人保留。 |

卖家编辑在售帖的标题、价格、描述或图片后重新审核。进入预约流程后，订单保存创建时的价格与物品摘要，供双方核对。

## 4. 代拿与抢单

**发布字段**包括任务类型、标题、物品简述、取件或采购区域、交付区域、截止时间、酬金和可选备注。抢单大厅展示任务类型、校区、粗粒度地点、截止时间和酬金，可按以下三类筛选。

| 首发任务类型 | 发单与履约要求 |
| --- | --- |
| 快递代拿 | 发单人填写驿站或快递柜及取件凭证。接单人取出快递后送到约定地点。 |
| 外卖代拿 | 发单人提供已下单付款的外卖取餐点及所需取餐信息。接单人领取餐品后送到约定地点。 |
| 校外代购 | 发单人填写校外店铺或采购区域、商品规格、数量和商品预算。接单人按清单代购并送回校区，遇缺货或超预算先征得发单人同意。 |

校外代购的商品预算和跑腿酬金分别展示。首版商品款暂由发单人与商家直接结算，接单人无需垫付购物或快递费用。

| 状态 | 进入条件与后续操作 |
| --- | --- |
| 待抢单 | 审核通过后进入大厅。发布者可取消，截止时仍无人接单则自动过期。 |
| 已接单 | 由一名同校区试点成员抢单成功。双方可查看履约所需信息。 |
| 履约中 | 接单者标记已取到或购得物品，并送至约定地点。 |
| 待确认 | 接单者提交已送达，发布者可确认完成或提交争议。 |
| 已完成 | 发布者确认送达，双方可查看历史记录。 |
| 已取消／已过期 | 保留状态与原因，停止抢单。当事人仍可查看记录。 |

- 多人同时抢单只允许一人成功。重复点击或网络重试返回已有接单结果，其他用户收到“已被接单”提示。服务端仅在任务仍待抢单且未到截止时间时接受抢单。抢单和撤单同时发生时，只有符合当前状态的操作可以写入。
- 接单后、取到或购得物品前，任一方可填写原因并取消。需要继续找人时，由发布者重新发布；此前接单者失去敏感信息访问权限。
- 取得物品后发生改址、联系失败、超时或未收到物品时，当事人发起争议，由运营跟进。已接单任务超过交付截止时间且仍未送达时标记履约超时并提醒双方。已送达且无人确认的任务保留待确认状态并提醒发布者。
- 取件码、取餐凭证、具体交接地点和必要联系方式通过订单私密字段提供。卖家接受预约或代拿抢单成功后，仅向相关当事人开放，终态后关闭普通查询入口。运营人员因争议访问时记录操作。

## 5. 页面与运营

| 页面 | 主要操作 |
| --- | --- |
| 二手 | 浏览、搜索筛选、查看详情、预约购买 |
| 代拿 | 浏览待抢单任务，按快递代拿、外卖代拿、校外代购筛选，查看详情并抢单 |
| 发布 | 选择发布二手物品或三类代拿任务之一，填写信息，查看审核结果 |
| 我的 | 我的发布、买入预约、代拿发布与接单、站内通知、举报申诉、隐私与账号管理 |
| 运营后台 | 审核图文、处理举报和订单争议、管理邀请码和违规账号、查询处理记录 |

- 二手和代拿帖子均先审核后公开。发布者可以查看待审核、通过或驳回结果，查看驳回原因并修改重提。接入图文内容检测，检测超时或失败时保留待审核状态，由运营处理。
- 列表与详情禁止公开取件码、完整个人住址、手机号、个人二维码等敏感信息。禁止发布违禁品、账号交易、代课代考和危险或需要专门资质的代办。
- 帖子详情和订单页提供举报入口。当事人可发起订单争议，业务记录保留原履约状态并暂停普通确认或取消，运营可记录处理结论，按事实恢复流转或关闭订单。后台保留处置原因、操作人和时间。
- 预约、接单、取消、交付、超时、审核与举报处理结果进入站内通知。列表和操作页提供加载、空结果、失败重试与状态已变化提示。
- 图片按公开帖子和私密凭证分别校验访问权。提供用户反馈和账号注销入口，明确个人信息用途、保存期限以及注销后的处理方式。

## 6. 微信提审与发布

1. 确定运营主体和 AppID，在微信公众平台按实际功能核对二手撮合、用户发帖和代拿接单（含校外代购）涉及的服务类目与资质。先确认实际账号可申请的范围，再定正式提审范围。具体类目和资质待选定主体后核对。 [微信公众平台](https://mp.weixin.qq.com/)
2. 在微信公众平台办理小程序备案，核对备案编号展示位置。准备部署环境，在公众平台配置适用的服务器域名，体验版通过 HTTPS 验证登录、图片上传和业务流程。 [工信部 APP 备案通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html) · [腾讯云备案说明](https://cloud.tencent.cn/document/product/243/97691)
3. 在平台填写用户隐私保护指引，使其与真机实际访问的个人信息、接口和权限一致。体验版验证用户拒绝权限后的提示与可继续使用的流程。 [腾讯云小程序隐私保护指引适配说明](https://cloud.tencent.com/document/product/1301/97930)
4. 准备审核账号或有效试点邀请码、演示帖子、订单数据及操作路径，覆盖发帖、预约、抢单、确认、举报和后台处置。提交微信审核，通过后发布正式版。

## 7. 首版验收

| 场景 | 通过标准 |
| --- | --- |
| 二手成交 | 甲发布并通过审核，乙预约并由甲接受。第三人无法同时获得有效预约。甲确认交接、乙确认收货后，双方看到已成交。 |
| 二手预约取消 | 卖家拒绝、买家撤回或预约超时后恢复在售，之后其他人可预约。 |
| 三类任务发布 | 分别发布快递代拿、外卖代拿和校外代购任务，审核通过后均可在对应分类找到并抢单。校外代购详情分别展示商品预算和酬金。 |
| 同账号发单与抢单 | 甲、乙各有一笔待抢任务。甲可抢乙的单，乙也可抢甲的单，两人各自的发单和接单记录均可查询，自抢操作返回失败。 |
| 代拿抢单 | 甲发布且审核通过，乙与丙同时抢单只有一人成功，重复提交保持同一结果。成功者标记取件和送达，甲确认后完成。 |
| 取消与超时 | 待抢任务到期后不可接单，抢单与撤单并发只有一个结果写入。取件后发生异常时可发起争议并进入后台处理。 |
| 隐私与越权 | 未入校区、无关成员和已取消的接单者无法通过列表、分享链接或接口获取订单私密信息。 |
| 审核与举报 | 违规帖子可驳回或下架，内容检测不可用时保持待审核，用户可查看处理结果，运营动作可追溯。 |
| 微信体验版 | iOS 与 Android 真机均可完成登录、上传、预约、抢单和确认。拒绝授权、断网或重复提交时页面有明确反馈。 |

## 8. 待确认

| 决策 | 初稿假设或需确认项 |
| --- | --- |
| 运营主体与试点校区 | 暂定单校区，运营主体、目标学校、校区合作方式和审核责任人待定。 |
| 校园身份机制 | 初期用邀请码准入。是否要求校方认证、校方邮箱或其他验真渠道，待根据试点条件确认。 |
| 时间与运营规则 | 确定待卖家处理时限、默认送达时限、争议响应时限、数据留存周期及违规处置规则。 |
| 结算方案 | 初期双方当面自行结算。若启用微信支付，另行明确交易主体、支付资质、退款、结算和争议处理责任。 |
