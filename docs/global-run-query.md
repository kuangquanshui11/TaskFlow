# 全局运行列表

更新：2026-11-05。

## 数据归属与查询路径

我将全局运行查询放在 Scheduler 的 execution 能力内，由 Controller 接收参数、IRunService 校验和编排、RunDataMapper 查询本服务 run_execution。Admin 用独立 RunQuery DTO 接收公开请求，校验参数后通过既有 Feign 客户端在本地 SQL 事务外调用 Scheduler；不查询 Worker Inbox，不关联 Admin 任务表。Gateway 沿用公共 API 路由，内部查询仍受控制密钥保护。

我保留 `/select?jobId=...` 的现有契约，新增 GET `/api/v1/runs/selectGlobal` 与内部同名动作。管理入口要求 run:read；前端入口仅向该权限开放，直接进入页面也检查权限，服务端仍独立拒绝越权。接口、参数与错误见 [API](api.md)。

## 时间、状态与分页

我按运行创建时间使用半开窗口 `[from,to)`，显式时间必须为 UTC、成对提供且最长 7 天。普通请求缺省最近 24 小时，只有精确 Run ID 可以不提供时间查询历史。所有条件取交集，精确 ID 不绕过显式时间、状态、任务或触发来源。

我只接受五种 Run 状态及 MANUAL/CRON 两种触发来源。任务 ID 不要求对应当前有效 Job，因此软删除后的运行仍能检索。列表不声称当前任务名称；配置变更不改变运行保存的任务 ID、版本和来源。Run ID 不匹配时返回空页，详情接口仍保留 404 语义。

我让列表和总数复用同一套参数化 WHERE 条件，并放在同一本地只读 REPEATABLE_READ 事务中。列表只读取摘要字段，不加载参数快照、不逐条查询 Attempt；attemptCount 使用已持久化的 current_attempt。排序固定为 created_at DESC、id DESC，避免相同创建时间产生不确定顺序。每页最多 100 条、最多第 10000 页；深页用户应缩小范围。

我复用现有 idx_run_created_state 和 idx_run_job_created 索引及 Run 主键，不新增表或迁移。时间窗、页大小和字段投影限制单次返回范围，不能据此承诺任意历史数据量下的查询性能；COUNT 和组合条件排序仍有数据库成本，大规模数据需要实际 MySQL 执行计划和负载验证。

## 控制台行为

我在 `/runs` 提供全局运行列表，包含创建时间范围、运行状态、任务 ID、触发来源和完整 UUID 筛选。默认 24 小时，可选 7 天、自定义和仅用于 Run ID 的不限时间。相对窗口在提交时固定；翻页、刷新、重试和页大小调整使用已提交条件，未提交的表单编辑不会影响结果。刷新不会自动扩大已固定的窗口，查询按钮会重新确定相对窗口。

我用浏览器时区展示日期及接收 datetime-local 输入，发送前转换为 UTC；页面明确显示时区。ID 支持复制完整文本，状态同时显示文字。移动端把表格改为卡片，长标识和错误消息换行。

请求时显示加载状态；失败清空当前结果并提供重试，空结果单独提示。前端校验失败保留表单并聚焦错误说明；离开页面取消读取，过期响应不得覆盖新结果。不自动轮询、不触发任务、不重放 POST。独立详情页、人工重跑、告警及审计属于后续能力。
